# SMS ASSOCIATES

## Centering Materials Rental & Inventory Management System

**Document Version:** 1.0
**Product Type:** Web-based Rental & Inventory Management System
**Business:** SMS Associates – Centering Materials Suppliers

---

# 1. PRODUCT OVERVIEW

SMS Associates is a web-based rental management and inventory management application designed for a centering materials rental business.

The system will replace manual bill management and scattered records with a centralized digital platform that manages:

* Customer records
* Rental bills
* Material selection
* Inventory
* Rental duration
* Advance payments
* Payment status
* Pending rentals
* Material returns
* Refund/additional payment calculations
* Customer rental history
* Customer documents
* Search and filtering
* Professional bill generation
* PDF export

The system must maintain historical records so that a bill created today can still be viewed and understood even months or years later.

# 3. PRIMARY OBJECTIVES

The application should:

1. Make bill creation fast and simple.
2. Automatically track material inventory.
3. Prevent accidental over-allocation of materials.
4. Maintain complete customer records.
5. Track materials currently rented out.
6. Track materials that are overdue or pending return.
7. Process partial and complete returns.
8. Automatically calculate actual rental charges.
9. Calculate refunds or additional amounts.
10. Maintain permanent rental history.
11. Generate professional bills.
12. Allow bills to be exported as PDF.
13. Provide fast search across customers and bills.
14. Provide a polished, professional ERP-style experience.

---

# 4. TARGET USERS

The primary users are SMS Associates staff/admin users.

The system should initially be designed as an internal business application.

The architecture should remain extensible so that multiple staff accounts and role-based access can be added later.

# 18. MATERIAL PRICING

Every material variant should have a configurable daily rental rate.

Example:

```text
Muttu Maram – 10 Feet
Rate: ₹5/day
```

The rate should be stored in the database.

The system must calculate:

```text
Quantity × Rate Per Day × Rental Days
```

Example:

```text
20 pieces
× ₹5/day
× 2 days

= ₹200
```

The calculation must be performed server-side for financial accuracy.

# 21. ADVANCE PAYMENT LOGIC

Advance is money collected before the final rental amount is known.

Example:

```text
Rate = ₹5/day
Expected Duration = 2 days

Rental Amount = ₹10
```

Customer pays:

```text
Advance = ₹20
```

The system must store:

```text
Estimated Rental = ₹10
Advance = ₹20
```

The advance must not be treated as the final rental charge.

# 36. ACTUAL RENTAL CALCULATION

At return time, calculate actual rental duration.

Example:

```text
Taken:
23 Sep

Returned:
26 Sep

Actual duration:
3 days
```

Then:

```text
Rate = ₹5/day
Quantity = 20
Actual Days = 3

Actual Rental:
20 × ₹5 × 3
= ₹300
```

Use the configured business rule for day counting consistently.

The calculation must be server-side.

---

# 37. REFUND CALCULATION

If:

```text
Advance > Actual Rental
```

then:

```text
Refund = Advance - Actual Rental
```

Example:

```text
Advance = ₹500
Actual Rental = ₹350

Refund = ₹150
```

---

# 38. ADDITIONAL PAYMENT

If:

```text
Actual Rental > Advance
```

then:

```text
Additional Amount Due
=
Actual Rental - Advance
```

Example:

```text
Advance = ₹500
Actual Rental = ₹650

Additional Amount = ₹150
```

Record the additional payment separately.

# 66. DATA INTEGRITY RULES

Important rules:

1. Bill number must be unique.
2. Customer must exist before creating a bill.
3. At least one material must exist in a finalized bill.
4. Quantity cannot be negative.
5. Inventory cannot accidentally become negative.
6. Returned quantity cannot exceed taken quantity.
7. Additional return cannot exceed remaining pending quantity.
8. Actual rental duration must be calculated consistently.
9. Historical rates must not change when master rates change.
10. Original bill number must remain unchanged after return.
11. Returned bills must remain accessible.
12. Inventory changes must be transaction-safe.

# 76. FINAL PRODUCT VISION

SMS Associates should ultimately feel like a purpose-built professional rental ERP.

The main workflow should be extremely simple:

```text
Customer arrives
      ↓
Create Bill
      ↓
Select Materials
      ↓
Check Inventory
      ↓
Collect Advance
      ↓
Generate Bill
      ↓
Materials Go Out
      ↓
Pending List Tracks Them
      ↓
Customer Returns Materials
      ↓
Process Return
      ↓
Calculate Actual Amount
      ↓
Refund / Additional Payment
      ↓
Update Original Bill
      ↓
Inventory Automatically Restored
      ↓
Permanent Rental History
```

The system should reduce manual calculation, prevent inventory mistakes, preserve historical records, and make everyday rental operations significantly faster and more organized.
